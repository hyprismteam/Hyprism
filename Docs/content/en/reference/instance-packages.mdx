# Instance packages

Hyprism exports a build or game definition as a JSON template or packages selected instance files in a ZIP archive. The instance wizard imports either format and full PWR game builds. See [Instances](/user-guide/instances-profiles-mods) for the user workflow.

## Selection and layout

| Kind | Included files |
| --- | --- |
| Build | All instance files, including game files, mods, worlds, and other user data. |
| Modpack | Files under `UserData/Mods/`, including its mod manifest. |
| Game | Instance files outside `UserData/` and `Client/mods/`. |

A build or game can be exported as a JSON template with `SchemaVersion` set to `2` and an `Instance` object containing its name, branch, numeric build, and optional version name. Build templates also contain notes; game templates omit them. Templates contain no file paths, mod metadata, or file contents. Modpack export requires ZIP. Schema `1` JSON manifests remain importable; their file and mod lists are ignored during import.

The template has this shape. `VersionName` and `Notes` are omitted when their values are not set.

```json
{
  "SchemaVersion": 2,
  "Instance": {
    "Name": "My instance",
    "Branch": "release",
    "Version": 72,
    "VersionName": "Pre-release",
    "Notes": "My settings"
  }
}
```

Every ZIP export contains a schema `1` `HyprismExport.json` manifest with `Kind`, source `InstanceMeta`, selected relative file paths and sizes, and installed mod metadata when mods are included. It also contains `Meta.json` for instance import and the selected files at their instance-relative paths. Symbolic links are excluded. Export writes to a temporary file beside the destination and replaces the destination only after completion. Cancellation removes the temporary file.

`InstancePackageService.ExportAsync` accepts optional `IProgress<int>` progress reporting. ZIP export reports the percentage of selected source file bytes copied, capped at 99 until the archive is complete and the destination is replaced. JSON export reports 0 before writing and 100 after replacement. Progress values do not represent compressed archive size.

JSON import requires a configured download source and creates a new uninstalled instance with the source name, branch, version, version name, and notes. It does not download or restore files. ZIP export assigns a new instance ID in `Meta.json`, while the manifest retains the source ID. ZIP import extracts the archive, assigns another ID if one already exists, and registers the imported instance.

Cancellation during ZIP extraction removes the temporary extraction directory before any instance files are moved into place.

## Full PWR imports

`IInstanceRepository.ImportFromPwrAsync` uses the registered `IButlerClient` to apply a full PWR build to an empty staging directory under `Instances/.import/<id>` on the instance filesystem. Butler is installed automatically when needed. The filename parser reads the numeric build from names such as `v72-linux-amd64`, `0_to_72`, or `72`; an unknown or nonpositive build is rejected before Butler runs. Differential filenames such as `71_to_72.pwr` and `v71~72-linux-amd64.pwr` are also rejected.

After Butler succeeds, the importer requires the current platform's game client, writes fresh `Meta.json` with a new ID, the `release` branch, and matching `Version` and `InstalledVersion`, then moves the directory into place and refreshes the instance registry. Incomplete imports stay outside the registry, and failure or cancellation removes their staging directory. Existing instances and the source PWR file are preserved. PWR imports do not require a configured game download source.

The implementation is in [InstancePackageService](../../../../Sources/Hyprism.Core/Game/Instances/InstancePackageService.cs) and [InstanceRepository](../../../../Sources/Hyprism.Core/Game/Instances/InstanceRepository.cs).
