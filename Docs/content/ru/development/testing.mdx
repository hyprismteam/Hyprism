# Тестирование

Запускайте тесты из корня репозитория. Каждый набор имеет отдельный проект и матрицу CI

```bash
dotnet test Tests/Hyprism.Core.Tests/Hyprism.Core.Tests.csproj
dotnet test Tests/Hyprism.LocalNode.Tests/Hyprism.LocalNode.Tests.csproj
dotnet test Tests/Hyprism.Desktop.Tests/Hyprism.Desktop.Tests.csproj
```

## Границы покрытия

| Набор | Основное покрытие |
| --- | --- |
| Core | Координация запуска, процессы, профили, загрузки, конфигурация, зеркала, патчи, моды |
| Local Node | HTTPS, токены, хранение аккаунтов, сертификаты, жизненный цикл процесса |
| Desktop | Модели представления, локализация, платформенные адаптеры, рендеринг и элементы UI |

Тесты Local Node закрепляют созданные сертификаты и отключают системные изменения доверия. Модульные тесты используют временные данные и mock-сервисы вместо живых аккаунтов, игры и внешних API

Тесты Desktop разделяют приложение Avalonia, dispatcher и композитор, поэтому выполняются последовательно. Ожидайте итоговое свойство или состояние; фиксированная задержка подходит только для намеренного снимка промежуточного кадра

## Запуск конкретных тестов

При разработке используйте фильтр полного имени

```bash
dotnet test Tests/Hyprism.Desktop.Tests/Hyprism.Desktop.Tests.csproj \
  --filter FullyQualifiedName~StringLocalizerTests
```

Создание скриншотов запускается отдельно по инструкции [сайта документации](/development/documentation#screenshots). Обычный запуск тестов пропускает съемку

## CI и ручные проверки

Core, Desktop и Local Node запускаются в отдельных reusable workflow, каждый с матрицей Ubuntu, Windows и macOS и `fail-fast: false`. Каждый job матрицы записывает GitHub Step Summary из TRX-файла с общим количеством, пройденными, пропущенными и ошибками. При падении запуска в сводку добавляется последняя ошибка в текстовом кодовом блоке, а TRX-файл загружается как artifact job

Элемент macOS матрицы Local Node также публикует apphost и проверяет HTTPS health с созданным центром в одноразовой связке ключей runner. Это шаг macOS job Local Node, а не отдельный test job. Он не проверяет интерактивный запрос доверия на компьютере игрока или полноценный запуск Hytale

Упаковка образует отдельную группу проверок. В `ci.yml` она запускается только после успешного завершения reusable workflow Core, Desktop и Local Node

Windows job упаковки также устанавливает и удаляет созданные пакеты MSI и EXE на одноразовом runner. Он проверяет общие ярлыки на рабочем столе и в меню «Пуск», их ссылки на лаунчер и очистку после удаления приложения. Ручной запуск той же проверки описан в [руководстве по упаковке Windows](/development/packaging).

При изменении соответствующей границы проверяйте системный композитор, диалоги и совместимость с игрой вручную. Для изменения документации выполняйте [проверку контента и статический экспорт](/development/documentation)
