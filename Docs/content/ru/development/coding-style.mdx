# Стиль кода и текста

Пишите для человека, которому предстоит разобраться в коде и безопасно его изменить

## Текст

- используйте прямые и понятные формулировки
- избегайте длинных тире
- не ставьте точку в конце последнего предложения абзаца, пункта списка, summary, param, returns или exception
- описывайте реальное поведение без маркетинговых и пустых фраз
- объясняйте причину ограничения, если она не очевидна
- оставляйте комментарии, которые объясняют замысел, совместимость или неочевидное ограничение, но не пересказывайте следующую строку

## XML-документация C# API

Каждый публичный метод должен иметь XML-документацию. Публичные типы и модели данных следует описывать, если их смысл не очевиден из кода

Публичный метод должен содержать

- `<summary>` с действием и его назначением
- `<param>` для каждого аргумента
- `<returns>` для каждого результата кроме `void`, включая `Task` и `Task<T>`
- `<exception>` для ошибок, которые должен учитывать вызывающий код

Пример интерфейса показывает формат документации, а не контракт лаунчера

```csharp
using System.IO;
using Hyprism.Core.Models;

public interface IProfileReader
{
    /// <summary>
    /// Загружает выбранный профиль из постоянного хранилища
    /// </summary>
    /// <param name="profileId">Стабильный идентификатор загружаемого профиля</param>
    /// <returns>Профиль при его наличии, иначе <see langword="null"/></returns>
    /// <exception cref="IOException">Возникает, если файл профиля не удалось прочитать</exception>
    public Profile? LoadProfile(string profileId);
}
```

Используйте `<inheritdoc/>` в реализации только тогда, когда интерфейс полностью описывает контракт

## Структура

- храните независимое от UI поведение в `Hyprism.Core`
- храните Avalonia-ресурсы и presentation state в `Hyprism.Desktop`
- используйте интерфейсы на границах хоста
- применяйте async I/O и передавайте cancellation token через сетевые и долгие операции
- не добавляйте зависимости представления в Core
- используйте `[GeneratedRegex]` для постоянных шаблонов и оставляйте runtime-регулярки только для действительно динамических выражений
- переиспользуйте `JsonSerializerOptions` вместо создания нового экземпляра при каждом вызове сериализации
- предпочитайте collection expressions и `System.Threading.Lock`, если их поддерживает target framework
- добавляйте `using` вместо повторения однозначного framework namespace в теле членов

Изменения документации должны соблюдать правила аудитории, примеров и скриншотов из [AGENTS.md](../../../../AGENTS.md)
