# Участие в разработке

Начните с issue или описания решения, если изменение затрагивает архитектуру, постоянные данные, аутентификацию или упаковку.

## Рабочий процесс

1. Создайте отдельную ветку и сохраните посторонние локальные изменения.
2. Реализуйте изменение в подсистеме, которой принадлежит поведение.
3. При изменении поведения добавьте регрессионный тест.
4. Обновите оба языка документации, затронутые примеры и скриншоты.
5. Запустите соответствующий [набор тестов](/development/testing).
6. Проверьте документацию и лицензионные заголовки.

Из корня репозитория.

```bash
python3 Scripts/license_headers.py --check
cd Docs
npm run check
PAGES_BASE_PATH=/launcher/docs npm run build
```

## Проверка перед ревью

- Опишите проблему, новое поведение и существенные компромиссы.
- Сохраните границы Core, Desktop и Local Node.
- Документируйте публичные контракты и изменения хранения.
- Исключите учетные данные, личную информацию, сборки и кэши.
- Убедитесь, что оба языка описывают реализацию.
- Укажите выполненные проверки и непроверенные платформенные границы.

Если коммит меняет только документацию, используйте префикс `docs:`. Подробные правила текста и скриншотов находятся в `AGENTS.md`.

## Первая правка интерфейса

1. Запустите самостоятельное приложение Desktop из корня репозитория.

   ```bash
   dotnet run --project Sources/Hyprism.Desktop/Hyprism.Desktop.csproj
   ```

2. Проследите цепочку владельцев на странице [Архитектура UI Desktop](/architecture/desktop-ui): токен, тема или класс, компонент, экран. Откройте соответствующий AXAML и храните строки и команды экрана в его view model.
3. Просматривайте исполняемый интерфейс во время правки. Avalonia предоставляет preview через расширение для Visual Studio, расширение Avalonia для VS Code и сторонний плагин AvaloniaRider для Rider. Preview требует самостоятельный desktop executable, такой проект есть у `Hyprism.Desktop`. См. [настройку preview Avalonia](https://docs.avaloniaui.net/docs/app-development/xaml-preview-and-design-settings).
4. После изменения поведения запустите headless-тест нужного экрана. `MainWindowRenderTests.ShellRendersAtSupportedDesktopSizes` использует фиксированные данные и проверяет широкую и компактную ширину.

   ```bash
   dotnet test Tests/Hyprism.Desktop.Tests/Hyprism.Desktop.Tests.csproj \
     --filter FullyQualifiedName~MainWindowRenderTests.ShellRendersAtSupportedDesktopSizes
   ```

5. Если видимый экран изменился, пересоздайте скриншоты на двух языках по [процедуре съемки](/development/documentation#screenshots).

Для оценки первого опыта заполните необязательные поля pull request: время до первой видимой правки, число файлов для одного общего состояния и повторные правки после ревью.

Краткое соответствие терминов для веб-разработчиков:

| Термин Web и CSS | Термин Avalonia | Применение в проекте |
| --- | --- | --- |
| `class` и `.selector` | `Classes` и селектор, например `Button.primary` | Назначайте класс контролу, общие setters храните у владельца стиля. |
| Разметка компонента | `ControlTemplate` | Описывает визуальное дерево и части семейства контролов. |
| Отображение модели в представлении | `DataTemplate` | Отображает типизированный элемент. Шаблон элемента храните рядом с экраном. |
| Слот компонента | `ContentPresenter` и `Content` | Позволяет вызывающему коду передать содержимое в общий шаблон. |
| Свойство или обработчик события | `Binding` | Связывает значения и команды с унаследованным `DataContext`; команды меняют состояние. |
| Проверка типа привязок | `x:DataType` | Задает модель для compiled bindings и выявляет ошибочные пути при сборке. |
| Переменная темы во время выполнения | `DynamicResource` | Получает общий токен, поэтому изменение темы доходит до его потребителей. |
| Локальное CSS-исключение экземпляра | Локальное значение XAML | Локальное значение имеет приоритет над setter стиля. Используйте его для намеренного особого поведения. |

Стили Avalonia выбирают контролы в визуальном дереве. Свойство наследуется, если это поддерживает сам Avalonia, поэтому общее состояние передавайте через стиль-владелец или явную привязку.

## Краткое описание UI-изменения

Добавляйте этот список в описание UI pull request.

```text
Затронутый экран или компонент:
Проверенные состояния:
Широкая и компактная ширина:
Английский и русский текст:
Скриншоты до и после:
Тесты и проверки документации:
```

## Отчеты об ошибках

Используйте [шаблоны GitHub](https://github.com/hyprismteam/Hyprism/issues/new/choose). Укажите платформу, версию лаунчера, шаги, ожидаемое и фактическое поведение, а также подходящие [логи](/architecture/data-and-cache).

Перед публикацией проверьте вложения на учетные данные и личные пути.
