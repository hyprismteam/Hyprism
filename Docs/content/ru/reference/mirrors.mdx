# Зеркала

Определение зеркала сообщает Hyprism, где источник перечисляет версии и выдает полные образы или дифференциальные патчи. Лаунчер поставляется с официальным источником без заранее настроенных сторонних зеркал игры

## Хранение и проверка

Определения находятся в `Mirrors/<id>.mirror.json` каталога приложения. `IMirrorCatalog.Save` проверяет ID, имя, версию схемы, тип источника и обязательную секцию

ID содержит строчные латинские буквы, цифры, точки, дефисы и подчеркивания, начинается с буквы или цифры и ограничен 64 символами. Текущая версия схемы: `1`

## Источник по шаблону

Полный пример использует зарезервированный домен и статический список версий. Замените адрес и версии значениями оператора источника

```json
{
  "SchemaVersion": 1,
  "Id": "example-source",
  "Name": "Example source",
  "Priority": 100,
  "Enabled": true,
  "SourceType": "pattern",
  "Pattern": {
    "BaseUrl": "https://example.org/game",
    "FullBuildUrl": "{base}/{os}/{arch}/{branch}/0/{version}.pwr",
    "DiffPatchUrl": "{base}/{os}/{arch}/{branch}/{from}/{to}.pwr",
    "VersionDiscovery": {
      "Method": "static-list",
      "StaticVersions": [7, 6]
    }
  }
}
```

| Поле Pattern | Назначение |
| --- | --- |
| `BaseUrl` | Значение для `{base}` |
| `FullBuildUrl` | Шаблон полной установки |
| `DiffPatchUrl` | Необязательный шаблон дифференциального патча |
| `VersionDiscovery` | Способ получения версий |
| `OsMapping`, `ArchMapping`, `BranchMapping` | Замена строк платформы или ветки |
| `DiffBasedBranches` | Ветки, для которых доступны дифференциальные патчи при отсутствии полного архива |

Шаблоны поддерживают `{base}`, `{os}`, `{arch}`, `{branch}`, `{version}`, `{from}` и `{to}`. Внутренние значения платформ включают `windows`, `linux`, `darwin`, `amd64` и `arm64`

При первой установке Hyprism сначала запрашивает опубликованный полный архив, даже если ветка указана в `DiffBasedBranches`. Если для целевой сборки нет полного архива, лаунчер проходит по опубликованным переходам от другого полного архива. В манифесте одного зеркала для той же ветки могут одновременно быть полные архивы `0_to_<version>.pwr` и патчи `<from>_to_<to>.pwr`.

Обнаружение поддерживает `static-list`, `json-api` с `Url` и `JsonPath`, `manifest` с адресом манифеста, `html-autoindex` с `Url` и необязательным `HtmlPattern`, а также `head-probe` для зеркал без индекса. Время выполнения регулярных выражений ограничено, некорректные выражения игнорируются.

`head-probe` проверяет полные PWR-файлы по `FullBuildUrl` запросами HTTP `HEAD`, начиная со сборки 1. Он находит последнюю последовательную сборку в пределах `MaxProbeVersion` и проверяет каждую младшую сборку перед добавлением в список. По умолчанию предел равен 256. Укажите `MinFileSizeBytes`, чтобы отсеять страницы перенаправления и неполные архивы. Если после пропуска в нумерации есть более новые сборки, без индекса обнаружение не найдет сборки за этим пропуском.

Объект `Headers` в корне определения применяется при обнаружении, проверке доступности и загрузке файлов. `{hytaleAgent}` раскрывается в `hytale-launcher/<version>`, а `{hytaleVersion}` раскрывается в текущую версию официального лаунчера. Автоматическое обнаружение защищенных PWR-файлов сохраняет в определении зеркала `User-Agent`, `x-hytale-launcher-version` и `x-hytale-launcher-branch`.

### Названия версий и билды

Лаунчер разделяет числовой идентификатор билда и понятное пользователю название версии. Билд используется для путей загрузки, цепочек патчей и совместимости экземпляров, а название версии показывается в списке создания экземпляра и его подробностях

Для JSON API поле `JsonPath` указывает на название версии или числовой билд. Если элемент является объектом, парсер ищет числовое поле `build`, `buildNumber`, `buildVersion`, `buildId`, `id` или `number`. Используйте `BuildJsonPath`, если путь к билду нужно указать явно

```json
{
  "VersionDiscovery": {
    "Method": "json-api",
    "Url": "{base}/versions",
    "JsonPath": "items[].version",
    "BuildJsonPath": "items[].build"
  }
}
```

Обнаружение по манифесту также читает названия из `versions[branch][build].version` и из `gameVersion` подходящих записей `files`. Это поддерживает манифесты, где в пути файла указан только числовой билд, например `0_to_27.pwr`. Индекс `files` задает реальные переходы патчей для запрошенных ОС, архитектуры и ветки. Мастер создания показывает сборку, только если до нее есть путь от полного архива. Общий раздел `versions` содержит названия, но сам по себе не делает сборку доступной для установки.

Официальный источник читает защищенный манифест `game-assets/version/{branch}.json` и при необходимости переходит по его подписанной JSON-ссылке. Полученное название связывается с последним числовым билдом из API патчей

Официальный источник разделяет эти значения таким же образом для метаданных, возвращаемых вместе с шагами патчей. Кэш версий хранит числовой билд и отображаемое название отдельно, а кэш патчей хранит опубликованные переходы для каждого зеркала. Отменённый запрос не помечает ветку свежей и не сохраняет неполный список источников, поэтому следующий запрос получает его заново. Старые снимки кэша версий после этого изменения обновляются один раз. Существующие файлы экземпляров без названия версии продолжают использовать числовой билд как запасной вариант.

## Источник с JSON-индексом

JSON-индекс предоставляет готовые ссылки вместо построения каждого адреса по шаблону

```json
{
  "SchemaVersion": 1,
  "Id": "example-index",
  "Name": "Example index",
  "SourceType": "json-index",
  "JsonIndex": {
    "ApiUrl": "https://example.org/index.json",
    "RootPath": "hytale",
    "Structure": "flat"
  }
}
```

`Structure` принимает `flat` для структуры ветка → платформа → имя файла → URL или `grouped` с отдельными группами base и patch. `PlatformMapping` и `FileNamePattern` адаптируют имена. Стандартное имя полного файла: `v{version}-{os}-{arch}.pwr`, патча: `v{from}~{to}-{os}-{arch}.pwr`

## Обнаружение и выбор источника

Автоматическая настройка Desktop вызывает `IMirrorDiscovery` для публичного HTTPS-адреса. UI отклоняет дубликаты, назначает ID, сохраняет определение и вызывает `ReloadMirrorSources`. HTTP допускается только для локальной разработки на loopback

Проверка доступности измеряет задержку и наличие версий для текущей платформы без загрузки игры. Официальная проверка использует действительную сессию официального профиля для защищенного API патчей

Официальный источник предпочтителен, когда может обслужить запрос. Выбор зеркала использует включенные источники и кэш скорости. Изменения источников применяются без перезапуска лаунчера
