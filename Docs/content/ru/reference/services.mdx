# Контракты Core

Desktop вызывает интерфейсы Core напрямую. `Bootstrapper.Initialize` регистрирует реализации по умолчанию и принимает callback для добавления сервисов хоста до сборки контейнера

## Карта контрактов

| Область | Контракты | Ответственность |
| --- | --- | --- |
| Конфигурация | `IConfigStore` | Настройки и выбранные идентификаторы |
| Прогресс | `IProgressReporter` | Прогресс и ошибки экземпляра |
| Версии | `IGameVersionCatalog`, `IVersionSource` | Списки, метаданные, выбор источника |
| Зеркала | `IMirrorCatalog`, `IMirrorDiscovery` | Хранение, обнаружение, создание источников |
| Экземпляры | `IInstanceRepository`, `IInstanceMigrator` | Пути, реестр, порядок, выбор, импорт, миграции |
| Загрузки | `IFileDownloader`, `IPatchManager`, `IButlerClient` | Передача и применение патчей |
| Среда выполнения | `IRuntimeProvisioner` | Java и Visual C++ |
| Запуск | `IGameLaunchCoordinator`, `IGameInstallationWorkflow`, `IGameLauncher` | Подготовка до старта процесса |
| Процессы | `IGameProcessTracker` | Идентификация, события, восстановление и выход |
| Консоль | `IGameConsoleService` | Буферы и события строк экземпляра |
| Моды | `IModManager` | Каталог, файлы, импорт, состояние, обновления |
| Официальный вход | `IHytaleAuthenticator`, `IOAuthCallbackPageRenderer` | OAuth, обновление токенов, callback-страница |
| Профили | `IProfileManager`, `IProfileRepository`, `IUserIdentityProvider` | Личность, жизненный цикл, порядок |
| Персонаж | `IAvatarCache`, `ISkinRepository` | Аватары и скины |
| Local Node | `ILocalNodeServiceFactory`, `ILocalNodeService` | Нода для запуска, доверие, привязка процесса |
| Возможности хоста | `IGpuProvider`, `IDiscordPresence` | Обнаружение GPU и activity presence |

Контракты расположены рядом с реализациями. `Application/Ports` содержит только предоставляемые хостом возможности, а не все интерфейсы проекта

## Чтение списка экземпляров

Потребитель получает самый узкий нужный интерфейс. Пример выводит сохраненные экземпляры без создания всего графа запуска

```csharp
using Hyprism.Core.Game.Instances;

static void PrintInstances(IInstanceRepository instances)
{
    foreach (var instance in instances.GetCachedInstances())
        Console.WriteLine($"{instance.Id}: {instance.Name}");
}
```

## Явный адрес запуска

Хост предоставляет открытие браузера. Пример рассчитан на установленный экземпляр и использует текущий активный профиль

```csharp
using Hyprism.Core.Accounts;
using Hyprism.Core.Game;

static Task LaunchInstalledAsync(
    IGameLaunchCoordinator coordinator,
    string instanceId,
    AuthUriPresenter openAuthorizationUri)
    => coordinator.LaunchAsync(instanceId, openAuthorizationUri);
```

Для новой установки вызовите `DownloadAndLaunchInstanceAsync` у `IGameInstallationWorkflow` и проверьте результат. Экземпляр передает явные ветку и числовую версию, а workflow не выбирает версию неявно. Отмена выполняется через `CancelDownload(instanceId)`. Различие описано в [жизненном цикле игры](/architecture/game-lifecycle)

ZIP-архив для импорта должен содержать `Meta.json` с явной числовой версией. Архивы без этих метаданных отклоняются

## События и отмена

Репозитории публикуют `InstancesChanged` и `ProfilesChanged` после изменений. Запуск и выход процессов используют типизированные события `IGameProcessTracker`. `IGameLaunchCoordinator.LaunchFailed` сообщает об ошибках или отмене, возвращенных сценарием запуска; предварительные проверки могут отправить ошибку через прогресс или завершиться раньше

`IProfileRepository.RecordPlayTime(profileId, elapsedSeconds)` добавляет время завершенной игровой сессии к общему времени профиля. Репозиторий экземпляров отдельно хранит общее время каждого экземпляра

Область прогресса связывает вложенные асинхронные операции с экземпляром. Смена стадии и завершение обходят ограничение частоты. Хост переносит обновления UI в dispatcher и отписывается при освобождении

Если контракт принимает `CancellationToken`, передавайте его в сетевые и файловые операции. Установка управляет отменой отдельно для экземпляра вместо параметра токена в публичной точке входа

## Контракт установки модов

`IModManager.InstallModFileToInstanceAsync` перед записью файлов разрешает выбранный файл CurseForge и его граф обязательных зависимостей. Операция устанавливает зависимости в глубину, сохраняет связи CurseForge в `InstalledMod` и возвращает `false` для неразрешенных обязательных зависимостей, циклов или уже установленного несовместимого мода. Необязательные связи сохраняются, но автоматически не устанавливаются

`IModManager.GetModDependenciesAsync` разрешает обязательные связи файла каталога и дополняет их доступными названиями, версиями и URL иконок для предварительного просмотра установки

Перегрузки `IModManager` с параметром источника ищут проекты, получают файлы и устанавливают их из `curseforge` или `modifold`. Modifold использует публичные HTTP-методы без учётных данных API. Перед загрузкой версия файла проверяется на совместимость с версией игры в экземпляре. Для Modifold не разрешаются зависимости каталога и не выполняется проверка обновлений CurseForge.

`GetInstanceInstalledMods` также читает корневой `manifest.json` из каждого JAR- или ZIP-архива и сохраняет идентификаторы плагинов Hytale, диапазоны обязательных и необязательных зависимостей и подсказки порядка загрузки. `RemoveInstalledModAsync` отказывается удалять мод, на который ссылается список обязательных зависимостей другого установленного мода

## Официальная аутентификация

`IHytaleAuthenticator.LoginAsync` создает OAuth PKCE challenge и передает URI авторизации хосту. Callback renderer возвращает браузеру HTML успеха или ошибки. `TokenStore` сохраняет сессии по профилям

`LoginAsync` сначала полностью отправляет HTTP-ответ локального callback-обработчика, а затем продолжает обмен токенов, поэтому браузер успевает отобразить страницу, пока лаунчер завершает вход

При переключении профиля текущая сессия перечитывается. Каталог версий может получить действительную сессию любого официального профиля, а запуск игры использует выбранный профиль. Авторизация загрузки и личность игрока решают разные задачи

Не записывайте access, refresh, identity и игровые токены в UI-диагностику. Одновременный запуск официального аккаунта контролируется `OfficialLaunchGate` и постоянным реестром процессов

## Сервисы Desktop

`IDesktopSettingsStore` адаптирует настройки для UI. `IHytaleNewsClient` и `IGitHubClient` отвечают за данные представления. Системные диалоги и обработчики ссылок остаются в Desktop

Версия релиза берется из `Hyprism.Desktop.csproj` и один раз настраивает `LauncherUserAgent` при старте. Потребители используют общее значение вместо собственных строк версии
