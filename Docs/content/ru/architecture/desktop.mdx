# Hyprism.Desktop

Desktop служит хостом приложения Avalonia. Он собирает сервисы Core, предоставляет системные возможности и преобразует их состояние в представления и команды

## Композиция и экраны

| Расположение | Ответственность |
| --- | --- |
| `Program.cs` | Регистрации сервисов, рендерер, точка входа |
| `App.axaml` и `App.axaml.cs` | Ресурсы, создание окна, запуск и завершение |
| `Shell` | Окно, навигация, overlay запуска, данные аккаунта и сборка экранов |
| `Screens/Instances` | Жизненный цикл экземпляров, выбор, запуск, активность, моды, каталог, миры, состояние консоли и представление экземпляров |
| `Screens/Profiles` | Карточки, активация, редактирование, создание и вход |
| `Screens/Settings` | Настройки, адаптер хранения, использование диска и представление About |
| `Screens/News` | Загрузка ленты и статей, координация кэша, состояние изображений, разбор HTML, статьи и представление новостей |
| `Integrations/GitHub` | Метаданные репозитория GitHub, коммиты, участники и API аватаров |
| `Platform` | Ссылки, папки, диалоги, память, GPU, кэш изображений |
| `Integrations/Discord` | Реализация контракта presence |
| `Localization` | Строковые ресурсы и переключение языка |

## Рамка окна

Shell использует модель [WindowDrawnDecorations](https://docs.avaloniaui.net/controls/primitives/windowdrawndecorations) из Avalonia 12. Главное окно расширяет клиентскую область в область оформления. В Windows выбирается `WindowDecorations="Full"`, чтобы сохранить нативные переходы DWM и привязку окна к областям Snap, а [WindowDecorations.axaml](../../../../Sources/Hyprism.Desktop/Shell/WindowDecorations.axaml) заменяет стандартное содержимое отрисованного оформления Avalonia

На остальных платформах через платформенное значение сохраняется `WindowDecorations="None"` и используется та же оболочка. В Linux в `Program.cs` включены клиентские оформления Avalonia X11, поэтому роли элементов превращаются в нативные запросы оконному менеджеру на перемещение и изменение размера. [Главное окно](../../../../Sources/Hyprism.Desktop/Shell/MainWindow.axaml) помечает область заголовка, кнопки управления и зоны изменения размера через `WindowDecorationProperties.ElementRole`; сохраняйте эту настройку вместе с `ExtendClientAreaToDecorationsHint` и не возвращайте ручное изменение позиции окна через Win32

Кнопки управления используют векторные ресурсы из `Assets/Icons/MaterialSymbols.axaml`. Иконки сворачивания и закрытия постоянны, а центральная кнопка переключается между `MaximizeIcon` и `RestoreIcon` при изменении `WindowState`. Для них сохраняйте стандартный курсор-стрелку отдельно от курсора-руки обычных кнопок действий, чтобы нативное определение зон заголовка не конфликтовало со стилями Avalonia

## Представления и состояние

В проекте включены компилируемые привязки. Представления объявляют `x:DataType`, модели предоставляют наблюдаемое состояние и команды. Code-behind обрабатывает ввод, компоновку, фокус и анимацию

`MainWindowViewModel` содержит только состояние Shell и собирает view model экранов. `InstancesViewModel` и `NewsViewModel` владеют состоянием своих экранов и подписками на сервисы. `MainWindow.axaml` передаёт эти дочерние модели в `InstancesView` и `NewsView`, поэтому привязки экранов не зависят от свойств Shell

Каждый каталог `Screens/<Screen>` является вертикальным UI-срезом. Он может содержать представление, его view model, локальные presentation model и Desktop-адаптеры, которые нужны только этому экрану

Пример привязки к существующей модели настроек

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             xmlns:settings="using:Hyprism.Desktop.Screens.Settings"
             x:DataType="settings:SettingsViewModel">
  <ToggleSwitch IsChecked="{Binding CloseAfterLaunch}" />
</UserControl>
```

Изменения наблюдаемых коллекций публикуются через UI dispatcher. При освобождении владельца нужно отписаться от событий сервисов и освободить изображения

## Общая основа UI

`UI/Foundation/Themes/HyprismTheme.axaml` предоставляет шаблоны окна, прокрутки, ввода текста, выделения, списков, выпадающих списков, прогресса, подсказок и всплывающих поверхностей. `UI/Foundation/Tokens` содержит примитивные и семантические значения. `UI/Components/ControlThemes.axaml` содержит именованные темы системных контролов. `UI/Components/Components.axaml` определяет общие семейства контролов, `UI/Components/ManagerStyles.axaml` владеет повторяющимися паттернами manager и detail, а `UI/Foundation/GlobalStyles.axaml` содержит стили приложения. Каждый экран подключает свой словарь стилей локально

На странице [Архитектура UI Desktop](/architecture/desktop-ui) описаны каталог компонентов, порядок ресурсов, правила размещения и контракт состояний

| Элемент | Ответственность |
| --- | --- |
| `AdaptiveMasterDetailHost` | Общая широкая и компактная навигация |
| `DeferredContentControl` | Отложенное создание и сохранение представлений |
| `WizardHost` | Состояние мастера, переходы и координация навигации |
| `OverlayModal` | Общая панель диалога |
| `FadingPopup` и `FadingComboBox` | Жизненный цикл всплывающих меню |
| `ReorderableListController` | Маркеры перетаскивания, превью и позиции |
| `NoteCard` | Информационные и важные примечания |
| `EmptyState` | Единая иерархия пустого состояния с иконкой, текстом и действием от экрана |
| `FormRow` | Общая компоновка подписи, подсказки и элемента редактирования |
| `SmoothScrollViewer` | Общая прокрутка колесом и precision touchpad; опциональная прокрутка средней кнопкой |

Длительности анимации принадлежат `MotionDurations` или общему элементу-владельцу. Проверки компоновки и рендеринга описаны в [руководстве по производительности](/development/avalonia-performance)

Все принадлежащие приложению scroll host используют `SmoothScrollViewer`, поэтому дельты колеса мыши и precision touchpad проходят через один easing-цикл по кадрам. Его шаблон использует `SmoothScrollContentPresenter`, который перехватывает wheel до стандартного мгновенного изменения offset в Avalonia. Прокрутка средней кнопкой включается отдельно и сейчас используется только в News. Scrollbar сохраняет постоянный layout-slot thumb шириной 6 px, а видимую ширину 3 px в обычном состоянии меняет через `RenderTransform`; будущие анимации толщины нужно делать через свойства рендеринга, а не через `Width`

## Сетевое содержимое

Клиенты новостей и GitHub используют общую HTTP-идентификацию. Разобранные новости хранятся в `Cache/News`, закодированные изображения в `Cache/Images`. Текст статьи готовится до декодирования изображений, а декодированные bitmap освобождаются при закрытии статьи

`RemoteBitmapLoader` используется экранами, которые показывают изображения. Он проверяет удалённые URL, использует `RemoteImageCache` при наличии и декодирует bitmap вне Avalonia dispatcher

Выбор файлов использует Avalonia `StorageProvider`. Обработчик ссылок сохраняет экранированные абсолютные URI, включая параметры OAuth. Эти возможности не принадлежат Core
