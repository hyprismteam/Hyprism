# Обзор архитектуры

Hyprism состоит из трех проектов .NET 10 и отдельного приложения документации Docusaurus

```text
Sources/
  Hyprism.Core/       игра, аккаунты, хранение данных, контракты
  Hyprism.Desktop/    Avalonia и адаптеры платформы
  Hyprism.LocalNode/  локальный HTTPS-сервис и управление процессом
Tests/
  Hyprism.Core.Tests/
  Hyprism.Desktop.Tests/
  Hyprism.LocalNode.Tests/
Docs/                двуязычный сайт документации
Packaging/           сборка пакетов и ресурсы установщиков
```

## Зависимости проектов

Desktop ссылается на Core и Local Node. Local Node ссылается на Core. Core не зависит от Avalonia и предоставляет контракты обоим хостам

Релизная упаковка создает apphost `Hyprism Launcher` и отдельный apphost `Hyprism.LocalNode` из одного publish

| Граница | Владелец | Подробнее |
| --- | --- | --- |
| Предметная логика и постоянное состояние | Core | [Ответственность Core](/architecture/core) |
| Представления, команды, диалоги, ссылки | Desktop | [Устройство Desktop](/architecture/desktop) |
| Автономная аутентификация и локальный API | Local Node | [Протокол и жизненный цикл](/reference/local-node) |
| Установка и процессы игры | Core с возможностями хоста | [Жизненный цикл игры](/architecture/game-lifecycle) |
| Хранение, миграции и диагностика | Сервис-владелец | [Данные и кэш](/architecture/data-and-cache) |

В лаунчере нет Electron, веб-фронтенда, IPC-моста или генерируемого TypeScript API. Desktop вызывает интерфейсы C# напрямую

## Запуск и завершение

1. Desktop настраивает рендерер, версию лаунчера и общий HTTP User-Agent
2. `Bootstrapper.Initialize` создает сервисы Core и применяет регистрации хоста
3. `App` создает окно, локализатор, выбор файлов, обработчик ссылок и модели представления
4. Асинхронная инициализация готовит необязательные сетевые данные под экраном загрузки
5. При завершении отменяется инициализация, освобождаются модели и сервисы, закрывается лог

Local Node, уже привязанный к игре, имеет отдельный жизненный цикл и работает до завершения игры

## Где добавлять поведение

Правила игры, аккаунтов, загрузки и хранения принадлежат Core. Состояние интерфейса и системные диалоги принадлежат Desktop. Local Node отвечает за локальный сервис и жизненный цикл вспомогательного процесса

Перед добавлением сервиса проверьте [справку по контрактам](/reference/services), а изменение покройте соответствующим [набором тестов](/development/testing)
