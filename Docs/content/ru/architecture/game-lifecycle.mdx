# Жизненный цикл игры

Операция запуска адресует явный ID экземпляра либо сохраненный текущий экземпляр. Выбор профиля не зависит от выбора экземпляра

## Установка и запуск

```text
Действие экземпляра в Desktop
  -> GameLaunchCoordinator (установленный экземпляр)
     или GameInstallationWorkflow (новая установка)
  -> выбор версии и патчей
  -> возобновляемая загрузка и распаковка Butler
  -> подготовка среды выполнения
  -> аутентификация и подготовка клиента в GameLauncher
  -> GameProcessTracker и логи экземпляра
```

`GameInstallationWorkflow` отклоняет одновременные установки одного экземпляра. Каждый экземпляр связан с явной веткой и числовой версией. Перед изменением файлов сохраняется `PendingVersion`, чтобы прерванное обновление можно было продолжить. Установленный экземпляр с совпадающей метаинформацией запускается по быстрому пути без обращения к источникам версий и зеркалам

`GameVersionCatalog` выбирает зеркало и раскрывает его заголовки для выбранного адреса загрузки. `GameInstallationWorkflow` и `PatchManager` передают эти заголовки в `HttpFileDownloader` для проверки размера файла и загрузки. Обнаружение зеркала и проверка доступности используют те же подстановки версии лаунчера. Способы обнаружения и поля заголовков описаны в [справке по зеркалам](/reference/mirrors).

Файлы игры кэшируются в `Cache/Game/Downloads`. Отмена передается через сеть, запись, распаковку и ожидание процессов. После успешной установки игра запускается автоматически

## Аутентификация и патчи

| Профиль и режим | Источник сессии |
| --- | --- |
| Официальный профиль | Официальный OAuth Hytale и игровые сессии |
| Локальный профиль, сетевой режим включен | Настроенный сторонний сервис |
| Локальный профиль, сетевой режим отключен | Отдельный Local Node для запуска |

`ClientPatcher` восстанавливает исходную резервную копию перед сменой цели клиента. Он перенаправляет поддерживаемые встроенные домены для сторонних и автономных сессий, сохраняя метаданные строк NativeAOT. В macOS состояние резервной копии хранится вне распознанного app bundle

Автономный запуск сначала запускает Local Node, получает токены и передает игре доверие к сертификату. Подробности приведены в разделе [Local Node](/reference/local-node)

## Среда выполнения и переменные

`RuntimeProvisioner` находит или загружает управляемую Java и устанавливает необходимые компоненты Visual C++ в Windows. Если метаданные официального JRE содержат SHA-256, архив проверяется до распаковки; при несовпадении архив удаляется

Лаунчер собирает аргументы Java, параметры GPU, DualAuth и пользовательские переменные. Пользовательские присваивания применяются последними. Фильтрация JVM исключает параметры, заменяющие управляемую настройку агента и исполняемого файла

## Владение процессами

`GameProcessTracker` сохраняет PID, время старта, экземпляр, профиль и владельца аутентификации. Восстанавливаются только записи, соответствующие живому процессу, поэтому повторное использование PID не связывает посторонний процесс с игрой

Разные экземпляры могут работать одновременно. Один экземпляр нельзя запустить дважды, а официальная аутентификация допускает только один клиент на владельца учетной записи Hytale

После автономного запуска Local Node передает владение от лаунчера к PID игры. При выходе лаунчер учитывает время и выполняет очистку, а Local Node останавливается вместе с привязанной игрой

Для UI используйте типизированные события процессов и прогресс экземпляра. Открытое окно лаунчера само по себе не определяет жизненный цикл игры
