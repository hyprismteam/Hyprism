# Данные и кэш

Hyprism разделяет постоянные данные игрока и восстанавливаемые загрузки и кэши

## Каталог приложения

| Платформа | Стандартный каталог |
| --- | --- |
| Windows | `%LOCALAPPDATA%/HyPrism` |
| macOS | `~/Library/Application Support/HyPrism` |
| Linux | `$XDG_DATA_HOME/HyPrism` или `~/.local/share/HyPrism`, если переменная не задана |

`HYPRISM_DATA` переопределяет весь каталог данных, только если тот уже существует. `InstanceDirectory` меняет лишь корень экземпляров

Для разработки используйте отдельный каталог

```bash
hyprism_data="$(mktemp -d)"
HYPRISM_DATA="$hyprism_data" dotnet run \
  --project Sources/Hyprism.Desktop/Hyprism.Desktop.csproj
```

## Постоянное состояние

| Путь относительно данных приложения | Содержимое |
| --- | --- |
| `Config.json` | [Настройки и выбранные идентификаторы](/reference/configuration) |
| `MigrationState.json` | Завершенные постоянные миграции данных Core |
| `Profiles/Profiles.json` | Список профилей и метаданные личности |
| `Profiles/<profile-id>/` | Данные профиля, сессии, скины и аватары |
| `Instances/Instances.json` | Реестр и порядок внутри корня экземпляров |
| `Instances/<instance-id>/Meta.json` | Ветка, версия, состояние установки, игровое время |
| `Instances/<instance-id>/UserData/` | Миры, моды и данные игры |
| `Mirrors/*.mirror.json` | Определения зеркал |
| `LocalNode/Accounts.json` | Автономные профили, скины и presence |
| `LocalNode/Certificate/` | Локальный центр сертификации и сертификаты сервера |
| `Runtime/GameProcesses.json` | Идентификация процессов между запусками лаунчера |

Пути экземпляров приведены для стандартного корня. Пользовательский корень переносит реестр и каталоги установок вместе

Перед проверкой миграций сохраняйте профили, миры, конфигурацию и локальные аккаунты. Файлы сессий и приватные ключи сертификатов не должны попадать в фикстуры и отчеты об ошибках

## Восстанавливаемые данные

| Путь | Содержимое |
| --- | --- |
| `Cache/Game/Versions.json`, `Patches.json` | Метаданные источников |
| `Cache/Game/Downloads/` | Файлы игры и возобновляемые `.part` |
| `Cache/News/` | Лента и разобранные статьи |
| `Cache/Images/News/`, `Github/` | Закодированные изображения |
| `Jre/`, `Butler/`, `DualAuth/` | Загруженные инструменты запуска |
| `LocalNode/Sessions/<session-id>/` | Временные файлы ноды и наборы доверия |

Не очищайте загрузки и файлы среды во время установки или работы связанной игры. После очистки кэша Hyprism загрузит или создаст данные заново при необходимости

## Логи запуска

Каждый процесс лаунчера создает отдельный каталог

```text
Logs/<yyyy-MM-dd_HH-mm-ss.fff>/
  launcher.log
  instance-<instance-id>.log
  local-node-<port>.log
  local-node-requests-<port>.ndjson
```

Логи экземпляра содержат стандартный вывод и ошибки игры в формате `время|уровень|источник|сообщение`. Время, уровень и источник HytaleClient сохраняются; строки стека исключения получают уровень `TRACE`. Логи Local Node содержат статусы маршрутов, длительность, жизненный цикл и ошибки; журнал неизвестных запросов не сохраняет заголовки и тела. Нода может продолжать запись после закрытия Desktop

## Правила миграции

JSON самого Hyprism использует PascalCase для имен файлов и свойств. `LauncherJsonFile` распознает старые имена и приводит их к каноническим, а чтение остается нечувствительным к регистру

`CoreMigrationRunner` применяет локальные миграции данных до того, как Desktop читает экземпляры, профили, сессии или моды. Он отмечает постоянный шаг только после успешного завершения, а сама миграция остается безопасной для повторного запуска после прерванного старта

`LegacyProfileConfigMigration` переносит старые поля личности в хранилище профилей. Миграции экземпляров и профилей поддерживают прежние каталоги. Миграция кэша переносит старые PWR и удаленные изображения в текущие папки

Названия версий являются повторяемым обогащением, а не одноразовой миграцией. Hyprism заполняет отсутствующие названия в метаданных экземпляра, когда настроенный источник может сопоставить сохраненный номер сборки

Проверяйте миграции на временных копиях старых данных. Не меняйте имена файлов игры и регистр внешних протоколов
